# Notice Note

本地优先的桌面笔记工具：Markdown 编辑、按「内容天」归档的资料库、天级复习提醒与每日回顾。数据全部存在本机目录，不需要账号或网络；Android 客户端是**只读离线查看器**。

## 项目结构

```text
notice_note_client_pc/   Windows 桌面客户端（Electron 主进程 + 经典脚本渲染层）
notice_note_client_app/  Android 客户端及 Capacitor 原生工程
scripts/                 构建辅助、静态检查
tests/                   node:test 单元与契约测试
release/                 统一构建产物目录
```

## 启动与构建

```powershell
npm install
npm run start:pc       # 启动 Electron 桌面客户端
npm run start:app      # 构建并运行 Android 客户端，需要设备或模拟器
npm run build:pc       # Windows 安装包
npm run build:app      # Android APK
npm test               # 单元 / 契约测试
npm run lint           # 语法检查 + 静态检查
```

源码改动只有 `npm run start:pc` 能直接看到；要让安装版生效必须重新 `build:pc`。
`editor-entry.js` 改动后需要重新生成 bundle：`npm run bundle:pc`。

## 笔记、提醒与回顾是同一批内容

产品的核心前提：**需要提醒的笔记 = 要回顾的笔记**。提醒负责「该看了」，回顾负责「再看一遍」，不是两套内容。

- 笔记与资源（PDF/Word/Excel/图片）放在 `.study_notice` 回顾目录下才进入回顾体系。应用启动时、以及切换存储位置后都会自动创建（并迁移旧名 `study_notice`），不需要手工建；该目录不能重命名、删除或移动。
- 天级提醒、回顾历史与回顾日志**按库隔离**：切换存储位置后新库从空白状态开始，旧库的复习日不会带到新库。
- 每个文件有一个**归天日期**（默认取创建时间），同一天的所有文件构成「一套」，彼此**平级**（没有主/次文件之分）。可在回顾面板用日期选择器改归天日期。
- **复习日**按「内容天」设置：在回顾面板给某一天加提醒（自动排期一次排下第 2、3、7、15、30 天，当天算第 1 天；或手选任意不早于今天的日期）。**复习日不跳周末**；IPC 层会拒绝早于今天的日期。
- 提醒到点通过系统通知 + 应用内通知中心提示；通知正文不会包含密码保护目录的标题。
- **每日自动回顾**按「最久没看过」排序选一套。回顾面板的完成入口分两级：今天推的那一套所在日显示「✓ 完成回顾」，其余有内容的日子显示弱化的「标记这一天已看过」（只把该套排到队尾，不减少以后的推送次数）；空白日不显示按钮。
- 回顾面板顶部的 **「顺序」「排期」两个小按钮**各开一个弹窗（按钮上带数量角标，再点一次收起）。**回顾顺序**按「下次会推什么」的顺序列出所有候选套，每条可「顶 / ↑ / ↓」调整，顺序持久化到 `config.json` 的 `dailyReviewOrder`（存 dayKey）。挂着未完成复习日的套不参与自动回顾，因此不出现在这里，改在**提醒排期**里——它按日期升序列出未完成的提醒，每行可直接改日期或取消，改期会把时间重置回默认时刻并清掉 `firedAt`。完成一次回顾会把这套从手动顺序里移除，避免它一直排在队首被反复推。
- 应用没运行时错过的提醒，重启后**不会**被写成「已看过」锚点；会补一条汇总通知，并保留在通知中心。待发汇总会持久化，应用在通知投递完成前退出也不会丢；只有客户端 ack 后才清除。
- 密码保护目录**一律不参与**每日自动回顾（即使本次会话已解锁），这样解锁状态变化不会让同一套内容时有时无。

旧版「按单篇笔记添加多个提醒」的 UI 已彻底移除。`note.reminders` 字段只作为历史数据保留，启动时由 `migrateRemindersToDays()` 归并成天级记录，不参与调度。

## 保存、恢复与密码保护边界

- 编辑是**手动保存**模型。未保存内容会写入 localStorage 恢复日志，退出前会统计 dirty 笔记并弹「保存并退出 / 不保存直接退出 / 取消」。
- **草稿是纯文字草稿**，草稿阶段不能插入/粘贴图片（包括从网页粘贴的富文本图片，会只保留文字并提示），请先「保存为笔记」再加图。
- 某一天的回顾内容如果**全部在密码目录**，到点仍会发提醒，但通知只说「有 N 个受保护文件待复习」，不带任何标题或文件名；混合可见与保护内容时，通知会补充「另有 N 个受保护文件」，同样不暴露名字。内容被删空的那一天只结算、不弹通知、也不记为「已看过」。
- **密码保护目录**里的未保存笔记不写恢复日志，草稿正文也不写 localStorage（只保留草稿条目，重启后提示需重新输入）。退出时会明确提示这类内容无法恢复；请记得手动保存。
- 密码保护只是**应用内访问控制**：磁盘上的笔记文件、`folders.json` 和手机离线包都是明文。设置密码时需要二次确认；忘记密码可关闭应用后编辑 `.notice-note/folders.json`，删除对应文件夹的 `passwordHash` / `passwordSalt`。
- `{{ ... }}` 糊住只是 PC 编辑器的**视觉遮挡**（点击展开），不是加密；手机端同样渲染成点击展开的遮挡块，但内容仍在离线包里。
- 远程图片由主进程下载时做了协议/私网 DNS/重定向/大小/类型校验；Markdown 里的 `https://` 图片**默认不会自动请求第三方**，编辑器显示占位按钮，点击后才加载。应用已限制新窗口与页面导航，并设置了 CSP。CSP 放行 `'unsafe-eval'` 是 PDF.js worker 编译所必需，打包后 Electron 不再显示相关安全警告。
- 大文件预览：PDF 超过 40 页时画布与文本层都按可视区域建立，打开全文搜索时自动补齐剩余页；Excel 超过 20MB 会拒绝应用内预览并提示外部打开，解析期间每 100 行让出一次事件循环，避免主进程被独占。**已知限制**：ExcelJS 的 `readFile()` 解析阶段仍无法中断，接近 20MB 的工作簿会让主进程卡顿数秒，界面会先显示「正在解析工作簿」提示。

## 存储位置

在「设置 → 存储位置」中显示当前路径，可「更改位置」或恢复「默认」。默认在 Electron `userData/notes/`：

```text
notes/                       笔记与资源文件（按文件夹组织）
notes/.study_notice/          回顾目录（应用自动创建）
notes/.notice-note/metadata.json            笔记元数据（含归天日期）
notes/.notice-note/resource-metadata.json   资源文件的归天日期
notes/.notice-note/folders.json             文件夹结构与密码哈希
userData/config.json          提醒、回顾历史、存储路径等设置
```

元数据、配置损坏时会先尝试 `.bak` 备份；两者都坏则把损坏文件另存为 `.corrupt-<时间戳>` 并用空值重建，应用照常启动，正文仍从磁盘扫描。

## 手机离线包

1. PC 客户端「设置」→「导出手机离线包」。
2. 把 `.notice-note-mobile` 传到手机，Android 客户端点「导入文件」。
3. 导入采用**整包预校验 + 单个 IndexedDB 跨 store 事务**：中途失败会整体回滚，旧的 snapshot 与附件都不会被部分覆盖。
4. 导入后列表、正文、附件全部读手机本地，无需联网。

手机端定位是**只读离线查看器**：图片可在应用内点开预览，PDF / Word / Excel / 压缩包只保存到离线包，手机端不预览（请在电脑端打开）。离线包中的密码目录是明文，手机端不校验密码，界面会明确标注「此离线包未加密」。

`build:app` 产出的是 **debug 签名、未做发布签名的 APK**，仅供自用，不用于分发；`versionName` 与根 `package.json` 的 `0.1.0` 对齐。
