# Notice Note

本地优先的桌面笔记工具：Markdown 编辑、按「内容天」归档的资料库、天级复习提醒与每日回顾、SM-2 记忆卡与 AI 判定。数据全部存在本机目录，不需要账号或网络；Android 客户端是配套的**查看与复习端**，通过局域网同步或离线包拿到同一份内容，可以看笔记、按天回顾，也能直接刷记忆卡。

## 项目结构

```text
notice_note_client_pc/   Windows 桌面客户端（Electron 主进程 + 经典脚本渲染层）
notice_note_client_app/  Android 客户端及 Capacitor 原生工程
scripts/                 构建辅助、静态检查
tests/                   node:test 单元与契约测试
release/                 统一构建产物目录
```

## 启动与构建

```powershell
npm install
npm run start:pc       # 启动 Electron 桌面客户端
npm run start:app      # 构建并运行 Android 客户端，需要设备或模拟器
npm run dev:app        # 手机端页面跑在浏览器里（默认 47821 端口），联调 UI 用
npm run build:pc       # Windows 安装包
npm run build:app      # Android APK
npm test               # 单元 / 契约测试
npm run lint           # 语法检查 + 静态检查
```

源码改动只有 `npm run start:pc` 能直接看到；要让安装版生效必须重新 `build:pc`。
`editor-entry.js` 改动后需要重新生成 bundle：`npm run bundle:pc`。

## 笔记、提醒与回顾是同一批内容

产品的核心前提：**需要提醒的笔记 = 要回顾的笔记**。提醒负责「该看了」，回顾负责「再看一遍」，不是两套内容。

- 笔记与资源（PDF/Word/Excel/图片）放在 `.study_notice` 回顾目录下才进入回顾体系。应用启动时、以及切换存储位置后都会自动创建（并迁移旧名 `study_notice`），不需要手工建；该目录不能重命名、删除或移动。
- 天级提醒、回顾历史与回顾日志**按库隔离**：切换存储位置后新库从空白状态开始，旧库的复习日不会带到新库。
- 每个文件有一个**归天日期**（默认取创建时间），同一天的所有文件构成「一套」，彼此**平级**（没有主/次文件之分）。可在回顾面板用日期选择器改归天日期。
- **复习日**按「内容天」设置：在回顾面板给某一天加提醒（自动排期一次排下第 2、3、7、15、30 天，当天算第 1 天；或手选任意不早于今天的日期）。**复习日不跳周末**；IPC 层会拒绝早于今天的日期。
- 提醒到点通过系统通知 + 应用内通知中心提示；通知正文不会包含密码保护目录的标题。
- **每日自动回顾**按「最久没看过」排序选一套。回顾面板的完成入口分两级：今天推的那一套所在日显示「✓ 完成回顾」，其余有内容的日子显示弱化的「标记这一天已看过」（只把该套排到队尾，不减少以后的推送次数）；空白日不显示按钮。
- 回顾面板顶部的 **「顺序」「排期」两个小按钮**各开一个弹窗（按钮上带数量角标，再点一次收起）。**回顾顺序**按「下次会推什么」的顺序列出所有候选套，每条可「顶 / ↑ / ↓」调整，顺序持久化到 `config.json` 的 `dailyReviewOrder`（存 dayKey）。挂着未完成复习日的套不参与自动回顾，因此不出现在这里，改在**提醒排期**里——它按日期升序列出未完成的提醒，每行可直接改日期或取消，改期会把时间重置回默认时刻并清掉 `firedAt`。完成一次回顾会把这套从手动顺序里移除，避免它一直排在队首被反复推。
- 应用没运行时错过的提醒，重启后**不会**被写成「已看过」锚点；会补一条汇总通知，并保留在通知中心。待发汇总会持久化，应用在通知投递完成前退出也不会丢；只有客户端 ack 后才清除。
- 密码保护目录**一律不参与**每日自动回顾（即使本次会话已解锁），这样解锁状态变化不会让同一套内容时有时无。

旧版「按单篇笔记添加多个提醒」的 UI 已彻底移除。`note.reminders` 字段只作为历史数据保留，启动时由 `migrateRemindersToDays()` 归并成天级记录，不参与调度。

## 保存、恢复与密码保护边界

- 编辑是**手动保存**模型。未保存内容会写入 localStorage 恢复日志，退出前会统计 dirty 笔记并弹「保存并退出 / 不保存直接退出 / 取消」。
- **草稿是纯文字草稿**，草稿阶段不能插入/粘贴图片（包括从网页粘贴的富文本图片，会只保留文字并提示），请先「保存为笔记」再加图。
- 某一天的回顾内容如果**全部在密码目录**，到点仍会发提醒，但通知只说「有 N 个受保护文件待复习」，不带任何标题或文件名；混合可见与保护内容时，通知会补充「另有 N 个受保护文件」，同样不暴露名字。内容被删空的那一天只结算、不弹通知、也不记为「已看过」。
- **密码保护目录**里的未保存笔记不写恢复日志，草稿正文也不写 localStorage（只保留草稿条目，重启后提示需重新输入）。退出时会明确提示这类内容无法恢复；请记得手动保存。
- 密码保护只是**应用内访问控制**：磁盘上的笔记文件、`folders.json` 和手机离线包都是明文。设置密码时需要二次确认；忘记密码可关闭应用后编辑 `.notice-note/folders.json`，删除对应文件夹的 `passwordHash` / `passwordSalt`。
- `{{ ... }}` 糊住只是 PC 编辑器的**视觉遮挡**（点击展开），不是加密；手机端同样渲染成点击展开的遮挡块，但内容仍在离线包里。
- 远程图片由主进程下载时做了协议/私网 DNS/重定向/大小/类型校验；Markdown 里的 `https://` 图片**默认不会自动请求第三方**，编辑器显示占位按钮，点击后才加载。应用已限制新窗口与页面导航，并设置了 CSP。CSP 放行 `'unsafe-eval'` 是 PDF.js worker 编译所必需，打包后 Electron 不再显示相关安全警告。
- 大文件预览：PDF 超过 40 页时画布与文本层都按可视区域建立，打开全文搜索时自动补齐剩余页；Excel 超过 20MB 会拒绝应用内预览并提示外部打开，解析期间每 100 行让出一次事件循环，避免主进程被独占。**已知限制**：ExcelJS 的 `readFile()` 解析阶段仍无法中断，接近 20MB 的工作簿会让主进程卡顿数秒，界面会先显示「正在解析工作簿」提示。

## 存储位置

在「设置 → 存储位置」中显示当前路径，可「更改位置」或恢复「默认」。默认在 Electron `userData/notes/`：

```text
notes/                       笔记与资源文件（按文件夹组织）
notes/.study_notice/          回顾目录（应用自动创建）
notes/.notice-note/metadata.json            笔记元数据（含归天日期）
notes/.notice-note/resource-metadata.json   资源文件的归天日期
notes/.notice-note/folders.json             文件夹结构与密码哈希
notes/.memory_card/cards.json               记忆卡与 SM-2 调度状态
notes/.memory_card/settings.json            记忆卡的 SM-2 参数
notes/.memory_card/answers.json             作答历史（AI 判定的原文、档位与理由）
userData/config.json          提醒、回顾历史、存储路径等设置（含 AI 判定的端点与 Key）
```

元数据、配置损坏时会先尝试 `.bak` 备份；两者都坏则把损坏文件另存为 `.corrupt-<时间戳>` 并用空值重建，应用照常启动，正文仍从磁盘扫描。

## 记忆卡（SM-2 间隔重复）

- 入口在左侧栏「记忆」。卡片和参数存在 `notes/.memory_card/`，跟着笔记库走：切换存储位置就是切换牌组，备份笔记库也会带上记忆卡。
- 从笔记快速建卡：在笔记条目上点右键 →「制作成记忆卡片」，正面预填标题、背面预填正文。正文会先清掉 markdown 噪音（图片、链接压成文字、反引号、成对 `**`、标题井号与引用符号），超过 4000 字按段落边界截断并在提示行说明。资料文件（PDF / Word）不提供这一项，卡片只存正反面纯文本。
- 卡片信息行右侧有「编辑」（或按 `E`）打开编辑器：正反面都能改，编辑器左下角是「删除卡片」，删除会一并清掉这张卡的复习记录。改完点「保存修改」回到学习页，调度状态（间隔 / ease）不动。
- 调度复刻 Anki legacy 的 SM-2：新卡先走分钟级学习步骤（默认 1 分 → 10 分）→ 按「毕业间隔」进入复习池 → 每次评分用 ease 与按钮系数推下次间隔；遗忘后进入重学步骤，`失误新的间隔` 决定是否继承原间隔（0% = 重置）。
- 天级间隔按**本地日切**算，和 Anki 一致：间隔 1 天 = 明天零点到期。晚上毕业的卡第二天一早就进「今日待复习」，不用等到前一天的同一时刻。逾期天数也按整天累加。
- 参数里的「新卡初始难度」沿用了一个错误译名，实际是 Anki 的 Starting Ease：250% = 2.5，**值越大间隔涨得越快**，不是越难。
- 每张卡可以挂多个**类型**（相当于 Anki 的 tag）。编辑器里输入类型名回车即可新建，也可以点「已有类型」里现成的；类型目录由卡片的 `types` 汇总，不需要单独维护一份。
- 类型筛选是**精确匹配**，不做前缀聚合。想让标签自带层级就用点分命名，例如 `微服务.熔断限流降级.细节`、`mysql.索引.地图`，类型条上每个按钮对应一格，一眼能看出是哪个域、哪块知识、什么粒度。缺点是它不会自动生成「只看 `微服务.*`」这类父级入口。
- 学习页统计下面一排是类型切换条（`全部` + 各类型，带张数）。选中某个类型后，侧边栏列表、学习队列、统计都只算这个类型；在某个类型下点「新建卡片」会自动预填该类型。
- 每天新卡上限按**当前筛选范围**算，和 Anki 的牌组日限额一个道理：按类型学时每个类型各有自己的额度。筛选状态只存在内存里，重启应用回到「全部」。
- 每天新卡默认上限 20（Anki 的牌组日限额），可在「算法参数」里改。学习中的卡按分钟级到期时间回来，不受这个上限影响。
- 落盘格式为 `{ "version": 1, "cards": [...] }`，每张卡保存 `types / state / step / interval / ease / dueAt / reps / lapses / introducedAt`。文件损坏时走 `.bak` → 空值重建，不阻塞启动。

### AI 判定掌握程度

- 作答框在**答案还没翻开时**就出现：看着问题回忆，提交后模型判「重来 / 困难 / 良好 / 简单」，判完才把背面翻出来。配了 AI 就没有「先显示答案再作答」这一步，否则等于边看答案边回忆。
- 作答框里 **Enter 换行、Shift + Enter 提交**。写长答案时回车基本都是想换行，用光回车提交会边写边误提交。判定结果出来后焦点已离开输入框，这时按 `Enter` 或空格才是「下一张」。
- 每张新卡自动把光标放进作答框，整条流程不用动鼠标。空格在 AI 模式下是把光标送进作答框，不是翻答案。
- 模型的判据写在 `lib/ai-judge.js` 的 system prompt 里。关键一条：**只复述标准答案、没有补充任何新信息，判「良好」而不是「简单」**——否则 easy 会泛滥，间隔被拉长到该忘的时候才发现。
- 评分的依据是**机制是否覆盖**，不是数值是否背对：背面里的 `50%`、`1s`、`20 次`、`70~80%` 这类参数都是可配置示例，标为「举例」「示例」或写在括号里的一律不作为得分点；只报数值不说机制才算没掌握。
- 端点是 OpenAI Chat Completions 兼容协议，配置在「设置 → 记忆卡 AI 判定」：`API 地址 / API Key / 模型名`。Key 存在 `userData/config.json`，不进笔记库，也不会进 git。
- 千帆的 deepseek 系列默认开推理，`reasoning_tokens` 会吃光 `max_tokens` 导致 `content` 为空。请求里带 `thinking: { type: "disabled" }` 关掉它；换到不认这个参数的端点时会自动去掉并重试一次。
- 判定失败（没配 Key、断网、超时、回复看不懂）一律退回手动四档，并在判定结果条上写明失败原因。断网也能正常复习；此时答案已翻开、不给重试入口，因为看了答案再判一次只会虚高。
- 结果条右侧有「改判」：模型判错时点开四档手选一档。主进程会用**评分前的卡片状态**重算，而不是在已调度的结果上再叠一次，所以连点两次不会把间隔乘两遍。
- 每次作答都进 `answers.json`（原文 + 档位 + 理由 + 时间），学习页下方「作答历史」按卡片展示，可单条删除。删卡片时连带清掉它的历史。历史里存着上次的作答原文，所以只在翻面后出现，免得在问题面漏答案。
- 顺手给模型带最近 3 次作答作背景，便于判断是进步还是退步；prompt 里明确写了「仅作参考，本次判定只看本次回答」，防止它为了体现进步而抬高档位。

## 手机客户端

两种取数方式，拿到的是同一份内容：

- **局域网同步**：PC「设置 → 局域网同步」开启并生成 6 位配对码，手机「设置 → 局域网同步」填电脑内网 IP 与配对码，点「立即同步」。之后首页顶部的「同步」按钮可以随时再拉一次。记忆卡参数由 PC 单向下发，手机端的作答与复习进度会合并回去。
- **离线包**：PC「设置」→「导出手机离线包」，把 `.notice-note-mobile` 传到手机，客户端点「导入文件」。导入采用**整包预校验 + 单个 IndexedDB 跨 store 事务**：中途失败会整体回滚，旧的 snapshot 与附件都不会被部分覆盖。

四个 Tab：

- **笔记**：列表、正文与附件。图片可在应用内点开预览；PDF / Word / Excel / 压缩包只保存到本地，手机端不预览（请在电脑端打开）。
- **日历**：对标 PC 的提醒日历。网格上三种标记——安排条数徽章、今日回顾绿点、已看过蓝点。点条目**原地展开抽屉**，不切月份、不改选中日。
- **回顾**：按天浏览，选一天看当天的笔记与资料，只读。
- **记忆**：复用 PC 的 SM-2 调度与 AI 判定（走同一份共享库，判据完全一致），可以刷卡、作答、看判定理由；复习进度会随下一次同步回传。

手机端有 6 套主题（`paper` / `blue` / `mint` / `dark` / `deepseek` / `deepseek_dark`），与 PC 极简主题同名同色，选择存在本地。键盘弹出时底部 Tab 会收起、下边距同步收窄，把空间让给作答区；键盘收起或视口恢复后自动还原。

手机端不校验密码：同步内容与离线包里的密码目录都是明文，界面上会明确标注「未加密」。

`build:app` 产出的是 **debug 签名**的 APK：可以直接安装和覆盖升级，但用的是 Android 默认调试证书，不适合上架应用商店；正式分发需要另配 release 签名。`versionName` 与根 `package.json` 对齐（当前 `1.1.0`，`versionCode` 同步递增）。

装机后走局域网同步（「设置」里填电脑内网 IP + 配对码）依赖三处原生配置，少一处手机会静默失败：

- `AndroidManifest.xml` 的 `android.permission.INTERNET`（Capacitor 库不自带，漏了所有 `fetch` 直接拒绝）
- `AndroidManifest.xml` 的 `android:usesCleartextTraffic="true"`（targetSdk 28+ 默认禁明文 HTTP）
- `capacitor.config.json` 的 `android.allowMixedContent`（App 跑在 `https://localhost`，向 `http://` 发请求属 mixed content；Capacitor 8 已移除旧的 `server.cleartext`）

`tests/android-packaging.test.js` 锁着这三处。删掉 `android/` 重建工程后要补回来，改完记得 `npm run sync:app` 再打包。

## 开发检查

```powershell
npm test
npm run lint
npm run lint:syntax
npm audit --omit=dev
```

`tests/` 用 Node 内置 `node:test`，覆盖日期月末 clamp、Windows 文件名清洗、资源回顾元数据落盘往返、离线包整包校验、原子写入/损坏降级，以及若干「防止 P0 问题回归」的源码契约检查。
